# Платежи за Голоса: сервер

Тут лежит всё, что нужно для покупки монет за Голоса ВКонтакте:

- `vk-payments.js` — Cloudflare Worker: отвечает ВКонтакте на уведомления о платежах
  и говорит игре, сколько монет начислить;
- `test.mjs` — тесты подписей и всего пути покупки, запуск `node server/test.mjs`.

Пока воркер не развёрнут, в игре **нет** раздела покупки: в `index.html` константа
`PAY_API` пустая, и витрина пакетов просто не рисуется. Это сделано намеренно —
кнопка «покупка скоро будет» это отказ модерации, а бесплатные способы получения
монет (ролик, ежедневная награда, страховка от нуля) работают сами по себе.

## Почему без сервера нельзя

Игра — статика на GitHub Pages. Но покупка за Голоса без серверной части невозможна
даже технически: на `VKWebAppShowOrderBox` ВКонтакте идёт не в игру, а на «адрес
обратного вызова» из настроек приложения — спросить уведомлением `get_item`, как
называется товар и сколько он стоит. Отвечать некому — окно оплаты не открывается
вовсе. Плюс правила VK требуют подтверждать покупку на сервере: клиентский ответ
подделывается из консоли, а Голоса настоящие.

Cloudflare Workers выбраны потому, что бесплатного тарифа хватает с запасом
(100 тыс. запросов в сутки), а состояние заказов — три ключа в KV. Ничего специфичного
для Cloudflare в коде нет, кроме `env.ORDERS`: md5 написан руками именно поэтому —
в Web Crypto его нет, и на другой платформе файл заработает как есть.

## Шаг 1. Развернуть воркер

```sh
npm install -g wrangler          # или npx wrangler
wrangler login
cd server
wrangler kv namespace create ORDERS        # id из вывода вписать в wrangler.toml
wrangler deploy
```

`wrangler.toml` лежит рядом, в нём надо заменить только `id` KV-хранилища.
После `deploy` wrangler напечатает адрес вида
`https://budka-payments.<ваш-субдомен>.workers.dev` — он понадобится дважды.

Проверить, что живо:

```sh
curl https://budka-payments.<субдомен>.workers.dev/items
```

Должен вернуться каталог из четырёх пакетов.

## Шаг 2. Настроить приложение ВКонтакте

В кабинете приложения (`vk.com/editapp?act=payments&id=<APP_ID>`):

1. Включить платежи, тип — **голосование/Голоса**.
2. **Адрес обратного вызова** — адрес воркера с `/callback` на конце:
   `https://budka-payments.<субдомен>.workers.dev/callback`.
3. Скопировать **защищённый ключ** (`Настройки` → «Защищённый ключ»). Это тот же
   ключ, которым подписаны и уведомления о платежах, и параметры запуска игры.
4. Товары в кабинете создавать не нужно: при работе через Callback API название и
   цену отдаёт сервер в ответ на `get_item`. Каталог — в начале `vk-payments.js`.

Ключ положить воркеру секретом (в репозиторий он не попадает — папка `server/`
уезжает на GitHub Pages вместе с игрой и читается кем угодно):

```sh
wrangler secret put VK_PROTECTED_KEY
```

## Шаг 3. Включить покупку в игре

В `index.html` найти `const PAY_API=''` и вписать адрес воркера **без** `/callback`:

```js
const PAY_API='https://budka-payments.<субдомен>.workers.dev';
```

Всё. Раздел «Пакеты монет за Голоса» появится в окне «Где взять монеты» сам —
он рисуется по каталогу, который игра запрашивает у `/items`, и только внутри VK.

## Шаг 4. Проверить живой покупкой

Тестовый режим включается в кабинете; администраторам и разработчикам приложения
покупки достаются бесплатно, а `notification_type` приходит с суффиксом `_test`
(воркер его срезает и обрабатывает как обычный). Что смотреть:

- окно оплаты открылось и в нём правильное название и цена — значит `get_item` дошёл;
- после подтверждения монеты появились в балансе за секунду-две;
- закрыть приложение сразу после оплаты и открыть заново — монеты должны прийти
  на старте (игра дёргает `/claim` при каждом запуске);
- `wrangler tail` — смотреть уведомления живьём, если что-то не сходится.

## Что уже проверено тестами

`node server/test.mjs` — 39 проверок, из них важные не про подписи, а про деньги:

- одно и то же уведомление, пришедшее трижды (ВКонтакте повторяет их при таймауте),
  начисляет монеты один раз;
- два `/claim` подряд дают монеты только в первый раз;
- чужой оплаченный заказ нельзя забрать своими параметрами запуска;
- подделанная подпись запуска — 403, а не «ну ладно»;
- возврат уже начисленных монет становится долгом и вычитается из следующей покупки;
- возврат до начисления не выдаёт монет вообще.

Всё это — свойства, ошибку в которых замечают не в тестах, а по жалобам игроков
или по потерянным деньгам, поэтому они проверяются автоматически и до отправки.

## Устройство хранилища

| Ключ | Что лежит |
|---|---|
| `order:<order_id>` | заказ: товар, монеты, `claimed`, `status` |
| `pending:<vk_user_id>` | список оплаченных, но не начисленных заказов игрока |
| `debt:<vk_user_id>` | монеты за возвращённые покупки, вычитаются из следующей |

Записи не удаляются: `order:*` — история покупок, по ней разбирают спорные случаи.
